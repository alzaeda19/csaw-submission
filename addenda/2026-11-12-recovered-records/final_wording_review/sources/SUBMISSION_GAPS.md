## What the newly recovered material changes

The 101-file collection preserves 15 Qwen setup attempts, prompt-only terminal history, scoped Claude observations and a bounded own-chat inventory. The chat review adds three clean-status messages, fourteen bitstream-history messages and four selected caveat excerpts. These counts describe records, not independent technical discoveries. All 51 compared final-generation/Codex/reviewer source files and the three Qwen received streams already matched published copies.

The old Claude plan that used published architecture was excluded as a technical source. Early Qwen drafts claiming AES-128 and a ready archive are retained only as explicitly labeled errors. They cannot be used to close the cipher or completion gaps. Historical claims that files were missing or records were not uploaded describe earlier stages and do not override the current guide.

Some older full conversations and interactive replies remain unavailable. Hidden reasoning, platform instructions and unrelated private material are deliberately excluded; they are not missing ordinary generation dialogue. A timed-out attempt never produced a completed answer, so no such answer can be recovered. New summaries never impersonate missing original transcripts.

## Scoring limits and tasks that are not mandatory

Negligible hardware overhead and a fully automated generation-to-test pipeline have not been established. Earlier detector studies do not certify this modification; the separate AES reference does not identify the recovered cipher. Documentation of a trigger is required by the brief and is not inherently disqualifying. Predictable output corruption is an allowed example in the original requirements.

The qualifier is simulation-only. Board programming, a physical timing result and key recovery are not missing mandatory deliverables; key recovery is a bonus. No new wrapper synthesis, silicon behavior, universal correctness or detector-evasion result is claimed.

All 262 original sealed-package files and the earlier sealed addendum remain byte-identical. This update changes documentation, adds authentic recovered records and rebuilds the delivery archive; it does not change or execute the design. No published solution was used for the updated explanation.
