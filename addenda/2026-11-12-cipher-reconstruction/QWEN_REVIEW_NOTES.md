# Qwen review and corrections

Two real text-only reviews used the existing local Qwen3 8B model through Ollama. Full request, received stream, reply, completion/usage receipt and hashes are retained under `ai_logs/`. Qwen had no tools, file access or execution permission. It did not author or run the reconstruction code. Codex wrote the independent interpreter, mathematical model, comparison harness and this report; the Trojan chat independently traced source Boolean cones and controls.

The first review correctly distinguished AES-table use from a complete AES implementation, but incorrectly suggested a key schedule, equal masks across byte positions, and counter/START-controlled direction. The second prompt explicitly corrected those points. The second reply still says a 32-bit mask “per byte position”; the actual mask is **32 bits total, four fixed 8-bit parts**. Its “4096 byte-value pairs” wording is imprecise: there are 4096 checked identities across initial/feedback and inverse compositions. Its pending-Icarus “physical implementation” phrasing is wrong: Icarus checks a digital simulation, never physical hardware.

The second prompt was prepared while the independent simulator was running. The simulator completed successfully before the Qwen call finished; the reply's pending status is historical and is superseded by `verification/icarus_run/RUN_RECEIPT.json`. These reviews are advisory records, not independent proof, and their unsupported wording is not adopted in the technical explanation. No numeric key guess, attack generation or published challenge solution was requested or used.
